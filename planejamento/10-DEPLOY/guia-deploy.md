# 🚀 Guia: Deploy para Produção\n\n## Pré-Requisitos\n- [ ] Build local passou (`npm run build`)\n- [ ] Testes passando\n- [ ] Migrations aplicadas em staging\n- [ ] Código está em main branch\n\n## 1. Deploy em Staging (Vercel Preview)\n\n```bash\n# Push para branch develop (Vercel cria preview automaticamente)\ngit push origin develop\n\n# Verificar em Vercel dashboard → Deployments → Preview URLs\n```\n\n**Testes em Staging**:\n- [ ] App carrega sem erros\n- [ ] Login funciona\n- [ ] Todas as features funciona\n- [ ] Sem erros no console (F12)\n- [ ] Performance aceitável\n\n## 2. Deploy em Produção (Vercel Main)\n\n### A. Criar Pull Request\n```bash\n# Em GitHub, criar PR de develop → main\n# Title: \"Release v1.0.0\"\n# Description: Listar features implementadas\n\n# Esperar code review\n# Merge quando aprovado\n```\n\n### B. Vercel Deploy Automático\nVercel automaticamente:\n1. Detecta merge em main\n2. Faz build completo\n3. Roda testes\n4. Deploy em produção\n\n```bash\n# Monitorar em Vercel dashboard\n# Procurar por \"Production Deployment\"\n```\n\n### C. Verificação Pós-Deploy\n\n```bash\n# 1. Acessar URL de produção\nhttps://seu-dominio.com\n\n# 2. Smoke tests\n☐ App carrega\n☐ Login funciona\n☐ Feature 1 funciona\n☐ Feature 2 funciona\n☐ Dashboard carrega\n\n# 3. Monitorar Vercel\n☐ Build passou\n☐ Sem erros de deployment\n☐ Logs limpos (F12)\n```\n\n## 3. Rollback (Se Necessário)\n\n```bash\n# Se precisa reverter:\ngit revert <commit-id>\ngit push origin main\n\n# Vercel automaticamente faz novo deploy\n# (voltando para versão anterior)\n```\n\n## 4. Monitoramento Pós-Deploy\n\n### Verificações Automáticas\n- Vercel: Status, Performance, Uptime\n- Sentry (se configurado): Erros em real-time\n- Google Analytics: Usuários, pageviews\n\n### Checklist Diário (Primeira Semana)\n- [ ] App está UP (sem 500 errors)\n- [ ] Usuários conseguem login\n- [ ] Sem erros críticos\n- [ ] Velocidade aceitável\n\n## 5. Variáveis de Ambiente em Produção\n\n```bash\n# Em Vercel Dashboard:\n# Settings → Environment Variables\n\n# Adicionar:\nNEXT_PUBLIC_SUPABASE_URL=https://prod-xxx.supabase.co\nNEXT_PUBLIC_SUPABASE_ANON_KEY=xxx\nNEXT_PUBLIC_API_URL=https://seu-dominio.com/api\n```\n\n⚠️ **Nunca** exponha `SUPABASE_SERVICE_ROLE_KEY` em variáveis públicas!\n\n## 6. Banco de Dados em Produção\n\n```bash\n# Migrations ANTES de fazer deploy\nsupabac migration up --db-url postgresql://...\n\n# Verificar se tudo está OK\n```\n\n## 🆘 Troubleshooting\n\n### Build falhou\n```bash\n# Verificar erros\ngit pull origin main\nnpm install\nnpm run build  # Deve passar localmente\n\n# Se falha, corrigir e fazer novo push\n```\n\n### App em branco (502 Bad Gateway)\n```\n• Verificar .env vars em Vercel\n• Verificar database connection\n• Revisar console.log de erros\n• Fazer rollback se necessário\n```\n\n### Usuários não conseguem login\n```\n• Verificar Supabase está UP\n• Verificar NEXT_PUBLIC_SUPABASE_URL está correto\n• Verificar RLS policies\n```\n\n## ✅ Checklist Final de Deploy\n\n- [ ] Build local OK\n- [ ] Staging testado\n- [ ] PR criado e aprovado\n- [ ] Merge em main\n- [ ] Deploy em produção OK\n- [ ] Smoke tests OK\n- [ ] Monitoramento ativado\n- [ ] Cliente notificado\n- [ ] Documentação atualizada\n\n---\n\n**Parabéns! 🎉 Seu projeto está em produção!**\n\n**Próximas etapas**: Monitoramento, feedback, melhorias\n"
