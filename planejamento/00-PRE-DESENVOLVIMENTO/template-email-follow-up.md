# 📧 Templates de Email - Fase 0

Templates prontos para comunicação com o cliente durante o Pré-Desenvolvimento.

---

## 📩 1. Email Pós-Entrevista (Agradecimento + Próximos Passos)

**Quando usar**: Logo após a entrevista inicial (mesmo dia ou dia seguinte)

**Assunto**: Obrigado pela entrevista - Próximos passos do projeto [Nome do Projeto]

```
Olá [Nome do Cliente],

Muito obrigado pelo tempo dedicado à nossa conversa hoje! Foi muito produtivo entender sua visão para o [Nome do Projeto].

Próximos Passos:
1. Vou organizar todas as informações em um PRD (Product Requirements Document)
2. Enviarei o PRD até [data] para sua revisão
3. Aí agendamos uma call rápida de 30 min para alinhamento final

Enquanto isso, se lembrar de algo importante que não mencionamos, por favor me avise!

Algumas perguntas que ainda tenho (opcional):
- [Pergunta 1]
- [Pergunta 2]
- [Pergunta 3]

Até breve!

[Seu Nome]
```

---

## 📋 2. Email Enviando PRD para Revisão (Primeira Versão)

**Quando usar**: Quando você terminar o rascunho do PRD

**Assunto**: PRD do [Nome do Projeto] - Pedido de revisão

```
Olá [Nome do Cliente],

Como prometido, segue o PRD (Product Requirements Document) do projeto [Nome do Projeto].

📎 **Anexo**: [Nome]-PRD-v1.0.pdf (ou link do Google Docs)

Este documento descreve:
✅ Objetivos do projeto
✅ Personas e usuários
✅ Features MVP (essenciais)
✅ Features pós-MVP (futuras)
✅ Timeline estimada
✅ Orçamento aproximado

Por favor, revise com atenção e me envie feedback até [data - dar 3-5 dias].

Pontos que gostaria de sua atenção especial:
- Seção 5 (Personas): Estão realistas?
- Seção 6 (Features MVP): Falta algo essencial ou tem algo que pode ser pós-MVP?
- Seção 8 (Timeline): As datas fazem sentido?

Depois da sua revisão, agendamos uma call rápida para alinhamento final (30 min).

Dúvidas? Estou à disposição!

[Seu Nome]
```

## 🔄 3. Email de Follow-up (Cliente Não Respondeu)

**Quando usar**: 3-5 dias após enviar o PRD sem resposta

**Assunto**: Re: PRD do [Nome do Projeto] - Gentil lembrete

```
Olá [Nome do Cliente],

Espero que esteja bem!

Estou enviando um gentil lembrete sobre o PRD do [Nome do Projeto] que enviei em [data].

Sei que você está ocupado, mas precisamos da sua revisão para prosseguir com o projeto no cronograma planejado.

Você consegue revisar até [nova data]?

Se preferir, posso:
- Fazer uma call rápida de 15 min para revisar juntos
- Enviar apenas as seções mais importantes
- Responder dúvidas específicas por aqui

Aguardo seu retorno!

[Seu Nome]
```

## ✅ 4. Email Após Feedback (Enviando Versão Atualizada)

**Quando usar**: Depois de incorporar o feedback do cliente

**Assunto**: PRD Atualizado - [Nome do Projeto] v1.1

```
Olá [Nome do Cliente],

Obrigado pelo feedback! Fiz as atualizações que você sugeriu.

📎 **Anexo**: [Nome]-PRD-v1.1.pdf

Principais mudanças (desde v1.0):
- [Mudança 1]
- [Mudança 2]
- [Mudança 3]

Por favor, confirme se agora está tudo ok para prosseguirmos.

Um simples "Aprovado, pode seguir" já resolve!

Obrigado!

[Seu Nome]
```

## 🎉 5. Email de Aprovação Final (Pedido de Confirmação)

**Quando usar**: Quando o PRD parece finalizado

**Assunto**: Aprovação Final - PRD [Nome do Projeto]

```
Olá [Nome do Cliente],

Ficamos muito felizes que o PRD está alinhado com sua visão!

Antes de começarmos o desenvolvimento, preciso da sua aprovação formal por escrito.

📎 **PRD Final**: [Nome]-PRD-v1.2.pdf

Pode responder este email confirmando?

Basta escrever: "Aprovado, pode começar!"

Isso garante que estamos 100% alinhados sobre:
✅ Escopo (features MVP)
✅ Timeline (data de lançamento)
✅ Orçamento (valor acordado)

Próximos passos após sua aprovação:
1. [Data]: Começamos a Fase 1 (Design Frontend)
2. [Data]: Reunião de kickoff do projeto
3. [Data]: Primeira entrega (milestone 1)

Aguardo sua confirmação para começarmos!

[Seu Nome]
```

## 📅 6. Email Agendando Reunião de Revisão do PRD

```
Olá [Nome do Cliente],

Duração: 30 minutos
Objetivo: Revisar PRD juntos e esclarecer dúvidas

Você tem disponibilidade em alguns destes horários?
- [Opção 1: Data/Hora]
- [Opção 2: Data/Hora]
- [Opção 3: Data/Hora]

Se nenhum funcionar, por favor sugira outros horários.

Até breve!

[Seu Nome]
```

## 🔴 8. Email de Alerta (Escopo Crescendo Demais)

**Quando usar**: Quando cliente quer adicionar muitas features ao MVP

**Assunto**: Impacto no timeline/budget - Novas features

```
Olá [Nome do Cliente],

Recebi suas sugestões de novas features:
- [Feature A]
- [Feature B]
- [Feature C]

Adoraria incluir todas, mas preciso alertar sobre o impacto:

📊 Impacto Estimado:
- Timeline: +[X] semanas
- Orçamento: +R$ [Y]
- Data de lançamento: De [data original] para [nova data]

Sugestão:
Podemos manter o MVP original (lançamento em [data]) e adicionar essas features na Fase 2 (pós-lançamento)?

Assim você valida o produto mais rápido e adicionamos features baseado em feedback real dos usuários.

Como prefere prosseguir?
1. Manter MVP original (mais rápido)
2. Expandir MVP (mais demorado)
3. Priorizar apenas [Feature X] agora

Aguardo seu retorno!

[Seu Nome]
```

## 🎯 Dicas de Comunicação

### ✅ Faça
- ✅ Seja claro e objetivo
- ✅ Use bullets e formatação (fácil de ler)
- ✅ Defina prazos claros
- ✅ Ofereça opções (não apenas "sim" ou "não")
- ✅ Confirme por escrito decisões importantes

### ❌ Evite
- ❌ Emails muito longos (>300 palavras)
- ❌ Jargão técnico excessivo
- ❌ Deixar sem prazo ("quando puder")
- ❌ Assumir que "silêncio = aprovação"
- ❌ Múltiplos assuntos no mesmo email
