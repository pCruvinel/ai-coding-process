## ✍️ Criação do Prompt (1-2 horas)

- [ ] Template [`template-prompt-figma-make.md`](./template-prompt-figma-make.md) aberto
- [ ] Seção **Objetivo** preenchida (2-3 frases claras)
- [ ] Seção **Público-alvo** definida
- [ ] Seção **Tipo de Aplicação** especificada
- [ ] Seção **Dispositivos** marcada (Desktop/Mobile/Ambos)

### Design & Estilo

- [ ] **Paleta de cores** definida:
  - [ ] Primary (hex code + uso)
  - [ ] Secondary (hex code + uso)
  - [ ] Accent (hex code + uso)
  - [ ] Background (claro/escuro/específico)
- [ ] **Estilo visual** descrito (moderno, minimalista, etc.)
- [ ] **Referências** visuais adicionadas (se houver)

### Componentes & Funcionalidades

- [ ] **Páginas principais** listadas (nome + breve descrição)
- [ ] **Componentes Shadcn/ui** necessários listados pelo nome
  - Consulte [`componentes-shadcn.md`](./componentes-shadcn.md)
- [ ] **Ícones** especificados (Lucide específicos ou "apropriados")
- [ ] **Imagens** descritas (keywords Unsplash)

### Dados & Backend

- [ ] Definido se precisa backend (Sim/Não/Talvez)
- [ ] Se SIM:
  - [ ] Tipo de dados listado
  - [ ] Funcionalidades backend descritas
  - [ ] Supabase marcado (Sim/Não/Sugira)
- [ ] Dados mock descritos (quantidade e tipo)

### Interatividade

- [ ] Nível de animações definido (Suaves/Mínimas/Elaboradas)
- [ ] Interações especiais listadas (drag & drop, filtros, etc.)
- [ ] Formulários descritos (campos + validações)

### Visualizações

- [ ] Gráficos necessários listados (line, bar, pie, area, ou nenhum)
- [ ] Dados dos gráficos descritos

### Extras

- [ ] Bibliotecas específicas mencionadas (se necessário)
- [ ] Recursos especiais listados (tema claro/escuro, etc.)
- [ ] Prioridades definidas

### Observações

- [ ] Observações adicionais anotadas
- [ ] Prompt revisado e validado
- [ ] Prompt copiado para uso

## 🆘 Problemas Comuns

### Figma Make gerou código que não funciona

✅ **Soluções**:
1. Revisar o prompt - foi específico?
2. Mencionar componentes Shadcn/ui pelo nome
3. Especificar bibliotecas necessárias

### Cliente quer muitas mudanças

✅ **Soluções**:
1. Limitar a 2-3 rodadas de feedback
2. Priorizar mudanças críticas para MVP
3. Documentar mudanças futuras separadamente

### Componentes não parecem Shadcn/ui

✅ **Soluções**:
1. Ser explícito: "Use componentes Shadcn/ui exatamente como na documentação"
2. Mencionar componentes específicos: "button, card, dialog, form"

### Design não é responsivo

✅ **Soluções**:
1. Adicionar ao prompt: "Design totalmente responsivo (mobile-first)"
2. Especificar breakpoints
